The workflow it replaces

Manual queue research is too slow for capacity-constrained markets.

A 50-200 MW project change can decide whether a data center site, storage project, or secondary-market acquisition is worth pursuing. The signal is usually public, but it is buried across PDFs, workbooks, XML feeds, CSV exports, and old utility portals.

QueueWatch gives teams a daily review queue of changed project records, not another folder of files to inspect by hand.

How it works

A serverless loop that separates cheap monitoring from expensive extraction.

01

Fingerprint

Daily checks compare ETag, Last-Modified, content length, hashes, or bounded probes.

02

Capture

Changed sources are saved to S3 with source metadata and parser invocation context.

03

Normalize

Deterministic parsers handle structured sources; Bedrock/Textract fallback supports messy PDFs.

04

Report

Project deltas are written to DynamoDB and exported as HTML, CSV, and JSON reports.
